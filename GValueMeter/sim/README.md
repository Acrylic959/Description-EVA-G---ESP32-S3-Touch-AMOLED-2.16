# 桌面模拟器（没有板子也能跑这套固件）

ESP32-S3 + CO5300 QSPI 屏 + QMI8658 + ES7210 这一套，**没有现成的模拟器能完整跑**：
Wokwi / Renode / QEMU 都没有 CO5300 的 QSPI 显示、也没有 QMI8658、ES7210 的模型，
把它们硬塞进去只会得到"外设初始化失败"的假象。

所以这里换了个更实用的做法：**把固件里和设备无关的那部分代码搬到电脑上跑**。

```
sim/
├── sim_main.cpp        合成"开车"数据 → 驱动 gmeter → 渲染 pet/pro → 输出 PNG
├── gen_font.py         生成 5x7 点阵字库（sim 显示文字用）
├── build.sh            一条命令编译 + 出图
├── stubs/              假的 Arduino 核心 / Arduino_GFX / Wire / Preferences /
│                       SensorQMI8658 / XPowersLib / esp_heap_caps / FreeRTOS
└── out/                跑完生成的 19 张截图（5 张是中文启动屏/提示条/滑动提示/校准浮层，10 张是正常工况，4 张是 G-G 圆盘）
```

## 它会跑哪些真代码

| 文件 | 在 sim 里 | 说明 |
|---|---|---|
| `gmeter.cpp` | ✅ 完整运行 | 单位自适应、零点校准、动态 G、峰值、颠簸、曲线——全是真的 |
| `pet_mode.cpp` | ✅ 完整运行 | 表情状态机 + 全部绘制 |
| `pro_mode.cpp` | ✅ 完整运行 | 仪表盘 + 三条 + 曲线 + 报警 |
| `hud.h` / `canvas_gfx.h` | ✅ | 绘图原语、PSRAM 画布、整帧推屏 |
| `mic_audio.cpp` | ⚠️ 跳过 | 需要真实 I²S，sim 里用脚本化 AudioSnapshot 代替 |
| `GValueMeter.ino` | ⚠️ 跳过 | 板级初始化（QSPI/I2C/PMU/按键）必须真机 |
| 七个按键 / NVS 掉电保存 / 30fps 时序 | ❌ | 只能真机验证 |

## 怎么跑

```bash
cd GValueMeter
bash sim/build.sh            # 编译并生成 sim/out/*.png
```

依赖只有系统自带的 clang++ 和 zlib（macOS 已内置）：

```
g++ -std=c++17 -O2 -Isim/stubs -I. -o sim/simrun \
    sim/sim_main.cpp gmeter.cpp pet_mode.cpp pro_mode.cpp cjk_font.cpp -lz
```

## 合成了一段什么样的"驾驶"

```
0.0 ~ 1.2s   静止（重力零点校准，屏幕会显示 ZEROING 进度）
2.6 ~ 4.1s   纵向 +0.38g 起步加速      -> ^^ 兴奋脸 + 速度线
5.0 ~ 6.4s   纵向 -0.33g 刹车          -> >< 震惊脸 + 感叹号
7.0 ~ 7.5s   竖直 3Hz / 0.55g 过减速带 -> X 眼 + 旋转星星（峰峰值 0.46g）
9.0 ~ 10.3s  侧向 +0.30g 右弯          -> 视线右移 + 侧倾动感线
11.0 ~ 12.3s 侧向 -0.30g 左弯
12.6 ~ 16.6s 麦克风：音乐 + 0.42s 一拍 -> 唱歌嘴 + 音符
17.0 起      切到专业模式，综合驾驶
18.3 ~ 19.5s 重刹 + 侧向，合成 1.11g   -> HIGH G 报警
```

每个事件都打印实测值，方便核对信号链：

```
[CAP] t=3.47s 02-pet-accel | mag=0.38 peak=0.38 lat=-0.00 lon=0.38 vert=0.00 ... bump=0
[CAP] t=7.20s 04-pet-bump  | mag=0.02 peak=0.53 ... p2p=0.46 bump=1
```

## 它替我们抓出来的问题

跑通这套模拟器之后改掉的真机 bug（不是模拟器专属问题）：

1. `hudCapsule` 用"t 条平行线"画粗线，斜线上会留下棋盘格状断口 → 改成按主轴逐列/逐行填充 + 圆头。
2. `hudArc` 折线采样太稀、层间距 1px 会漏点 → 改 0.5px 分层、约 1px 一个采样点。
3. 大号七段数字画了"灭段"（10% 亮度的幽灵轮廓），远看像 `8` → 去掉灭段，只留亮段。
4. 专业模式大数字与 HIGH G 横幅、`COMPOSITE ACCELERATION` 说明文字重叠 → 数字下移并缩到 92px 高。
5. HIGH G 横幅原来只在闪烁相位出现，一半时间看不到 → 横幅常亮（底色呼吸）、只有红框闪。
6. 三轴条标签原为 `X/Y/Z`，但显示的是 lat/lon/vert 分量，改了轴向映射就全错 → 改为 `LAT / LON / VER`。
7. 宠物感叹号太细太长（像一根头发）→ 加粗到 12px、缩短到 20px。
8. 颠簸星星太暗 → 提亮并放大。
9. 张嘴表情偏小 → 椭圆放大。

做完中文界面之后，模拟器又抓出这几条：

10. **七段数字 `1` 和后面的 `5` 粘在一起**，`0.15` 看上去像 `0.6` → 数字间距从 `0.75t+1` 加到 `t+2`，且 `1` 之后再多让 `0.6t`（`ssMeasure` 同步改，否则右对齐会偏）。
11. `hudPanel` 用库里的 `drawRoundRect` 描边，四个角的圆是单像素跳点，屏幕上看是虚线框 → 自己写 `hudRoundBorder()`（4 段胶囊 + 4 段 1/4 圆弧）。
12. 宠物脸边缘有明显锯齿缺口（描边弧比填充小半像素，逐行对不齐）→ 改成"由外向内三层收缩填充"，边缘干净。
13. 中文点阵生成器把位图行序搞反了，字是上下翻转的（`值` 看起来像 `直` 的镜像）→ `NSBitmapImageRep` 的内存是自上而下，不再翻转行。
14. 报警横幅压在数字上、峰值标注重叠 `0.8` 标注 → 横幅上移到 16..58（报警时顶部标题让位），图内标注改成曲线下方统一图例。

同时它也验证了 `gmeter.cpp` 的链路是对的：0.38/0.33/0.30 的输入对应 0.38/0.33/0.30 的输出，
0.55g 的颠簸产生 0.46 的竖直峰峰值并触发一次 `bumpSeq`，重刹合成 1.11g 越过 0.8 阈值。

## 想换场景自己玩

改 `sim_main.cpp` 里的两个函数就行：

- `motion(t, ax, ay, az)`：合成加速度（单位 g，`ay` 是竖直轴、`ax` 侧向、`az` 纵向，
  重力固定在竖直轴 1.0g，零点校准会把它减掉）。
- `audioAt(t, a)`：麦克风电平 / 是否有音乐 / 节拍序号。
- `CAPS[]`：想在哪些时刻、哪个模式下截图。

改完重跑 `bash sim/build.sh`，`sim/out/` 里的 PNG 就是新画面。
真机阈值不要在这里调——这里调的是"输入激励"，阈值仍然在 `pin_config.h`。

15. 面板右下角有个"方缺口"（`hudPanel` 用 `fillRoundRect` + 四条 2px 胶囊描边拼圆角，端头处露缝）→ 改为**逐行按圆角内缩**自己填：每行算 `inset = r - √(r²-dy²)`，行首尾 2px 画描边、首尾两行整行画描边，圆角连续不断。
16. 面板描边在拐角"过冲"（整行 top/bottom 描边比曲线宽）→ 同上，顶/底两行改成按当行内缩宽度画。
17. 七段数字 `1` 中间有接缝（b、c 两段各画一根胶囊，共线处重叠出毛刺）→ `ssDigit` 对 `1` 直接画一根通条；同时 `1` 的字符宽从 `0.55h` 收到 `1.35t`，`0.11` 不再被拉成 `0.1 1`。
18. 16px 的「零」糊成一团（笔画太多，阈值 128 二值化后粘连）→ 文案避开生僻复杂字，校准相关改成「校准中 %d%%」「校准中，请保持车身水平静止」。
19. 颠簸星星画成"炸毛的米字"（`hudStar` 是 8 条胶囊射线）→ 新增 `hudSparkle()`：两条菱形轴并集的四角星 ✦，自带一圈淡光；并把绕行角度错开 45°，不再压住嘴。
20. 曲线标题「G值曲线 / 120点 · 12秒」压在图框上边线 → 单独占一行（y=300），图框下移到 326。
